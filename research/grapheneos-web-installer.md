# GrapheneOS web installer: lessons for Light Phone III

Reviewed on 25 September 2026 without connecting to a device. The official [GrapheneOS source index](https://grapheneos.org/source#services) identifies the website repository. Examined website commit [`7fce0efbe2f7f920152f00d38ff35204070f547a`](https://github.com/GrapheneOS/grapheneos.org/tree/7fce0efbe2f7f920152f00d38ff35204070f547a) and its bundled fastboot library, corresponding to [`ffe7e270061b95fe0f0f3abd1aa7d3c28999d1d9`](https://github.com/GrapheneOS/fastboot.js/tree/ffe7e270061b95fe0f0f3abd1aa7d3c28999d1d9). The library's `src/fastboot.ts` matches the website source map byte for byte.

## Useful patterns

- **Reconnect at the point of use.** Each action calls `ensureConnected()` against the live USB object's readiness. The library reuses a single authorised device or opens the chooser when there are zero or multiple devices. It validates bulk endpoints, opens the device, attempts a reset, selects configuration 1 and claims interface 0. These are reusable ideas, but the fixed interface assumptions require checking against Light Phone III. [Page connection helper](https://github.com/GrapheneOS/grapheneos.org/blob/7fce0efbe2f7f920152f00d38ff35204070f547a/static/js/web-install.js#L208-L217), [library connection](https://github.com/GrapheneOS/fastboot.js/blob/ffe7e270061b95fe0f0f3abd1aa7d3c28999d1d9/src/fastboot.ts#L103-L180), [chooser](https://github.com/GrapheneOS/fastboot.js/blob/ffe7e270061b95fe0f0f3abd1aa7d3c28999d1d9/src/fastboot.ts#L223-L245).
- **Give reconnection its own visible action.** During flashing, progress is replaced with a reconnect button that calls `connect()` from a user gesture. The library requests this on Android and otherwise waits for a USB connection event. [Reconnect UI](https://github.com/GrapheneOS/grapheneos.org/blob/7fce0efbe2f7f920152f00d38ff35204070f547a/static/js/web-install.js#L280-L297), [wait logic](https://github.com/GrapheneOS/fastboot.js/blob/ffe7e270061b95fe0f0f3abd1aa7d3c28999d1d9/src/fastboot.ts#L184-L215).
- **Treat an already achieved state as success.** Unlock checks `getvar:unlocked` first and returns a friendly already-unlocked result. Otherwise it issues `flashing unlock`; lock issues `flashing lock`. Both say the operation was *triggered*, with physical confirmation and data-wipe instructions beside the button. This wording usefully avoids claiming that command acknowledgement proves the user's final choice. [Unlock](https://github.com/GrapheneOS/grapheneos.org/blob/7fce0efbe2f7f920152f00d38ff35204070f547a/static/js/web-install.js#L219-L241), [lock](https://github.com/GrapheneOS/grapheneos.org/blob/7fce0efbe2f7f920152f00d38ff35204070f547a/static/js/web-install.js#L351-L367), [physical instructions](https://github.com/GrapheneOS/grapheneos.org/blob/7fce0efbe2f7f920152f00d38ff35204070f547a/static/install/web.html#L270-L276).

## Caveats before reuse

The library's reconnect handler accepts the next authorised USB connection without checking that its serial matches the previous phone. Its disconnect handler resolves a wait but does not explicitly clear the stored device. `getVariable()` has a 10-second timeout; generic `runCommand()` has no equivalent timeout here. Keep Light Guide's serial binding and explicit handle cleanup, and invalidate live readiness on disconnection. Do not copy the event handlers verbatim. [Connection events](https://github.com/GrapheneOS/fastboot.js/blob/ffe7e270061b95fe0f0f3abd1aa7d3c28999d1d9/src/fastboot.ts#L248-L279), [commands and timeout](https://github.com/GrapheneOS/fastboot.js/blob/ffe7e270061b95fe0f0f3abd1aa7d3c28999d1d9/src/fastboot.ts#L329-L373).

The page keeps operation flags in memory and stores downloaded images in IndexedDB; it has no persisted write journal or resume protocol. Buttons are enabled on initialisation, and only download/flashing flags drive its busy-state logic. This is not evidence that refreshing is safe after a Light Phone manufacturing-data write. Keep the durable write journal separate from live USB readiness. Reconnection should enable inspection/recovery without clearing an uncertain write or automatically repeating it. [Cache](https://github.com/GrapheneOS/grapheneos.org/blob/7fce0efbe2f7f920152f00d38ff35204070f547a/static/js/web-install.js#L85-L176), [button/state handling](https://github.com/GrapheneOS/grapheneos.org/blob/7fce0efbe2f7f920152f00d38ff35204070f547a/static/js/web-install.js#L369-L470).

## Downloads, verification and Pixel-specific operations

The wrapper selects an allowlisted Pixel product, fetches its stable-release metadata over HTTPS and caches a named ZIP. It does not perform a detached signature or cryptographic image-digest check in this download path. The HTML's SHA-256 integrity attribute concerns the JavaScript bundle, not the downloaded factory image. GrapheneOS instead documents post-installation verification using verified boot and attestation. Do not present its download code as a ready-made firmware-authentication solution. [Release selection/download](https://github.com/GrapheneOS/grapheneos.org/blob/7fce0efbe2f7f920152f00d38ff35204070f547a/static/js/web-install.js#L243-L277), [script integrity](https://github.com/GrapheneOS/grapheneos.org/blob/7fce0efbe2f7f920152f00d38ff35204070f547a/static/install/web.html#L29-L33), [verification guidance](https://github.com/GrapheneOS/grapheneos.org/blob/7fce0efbe2f7f920152f00d38ff35204070f547a/static/install/web.html#L367-L388).

Do not port its product list, release URLs, OTA snapshot cancellation, factory-image flash flow, `avb_custom_key` removal or relock workflow into an unlock-only Light Phone tool. These implement GrapheneOS installation assumptions. In particular, upstream's generic `flashing unlock` does not implement or validate Light Phone III's manufacturing-data preparation. [Flash flow and key removal](https://github.com/GrapheneOS/grapheneos.org/blob/7fce0efbe2f7f920152f00d38ff35204070f547a/static/js/web-install.js#L299-L349).
